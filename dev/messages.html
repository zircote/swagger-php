Writing messages ​

How the spec pipeline words its warnings, errors and exceptions, and which level each one takes. This covers Builder, Resolver, the Assembler, the augmenters, the merge strategies, the compilers, plugins and the Spec attributes. Classic keeps its own messages until it is removed in 8.0.

Form ​

  1. Subject first, named as a user would search for it: Schema "Pet", Property Pet::$name, Operation "getPets". No internal class or processor names such as Ref:.
  2. What is wrong, then what happens, in one of the outcomes below. A hint on how to fix it follows a semicolon: …, omitted; use url instead.
  3. Location last, in <source>, wherever it is known. The message of an exception that caused the problem goes last instead, after a colon: …, skipped: <reason>.
  4. User values in double quotes, spec keywords bare (const, paths).
  5. Sentence case, no trailing period, no em dash.

The outcomes, one phrasing each:

OutcomePhrasingFor example
A class, member, plugin or source is not readskippedClass "Foo" cannot be loaded, skipped: …
Something read has no effectignoredConfig option "x.y" is unknown, ignored
Something declared is left out of the documentomittedWebhooks are not supported in OpenAPI 3.0, omitted
Something is removed after it was addedremovedComponent "#/components/schemas/Foo" is unreferenced, removed
One of several declarations winsthe last one kept, or the merge mode's own wordsSchema "Pet" is declared more than once, the last one kept in …
Something takes the place of what was declaredusing ……, using enum fallback
A field is left without a valueleft emptyRequest body "Foo" in … matches no request body, left empty

A message about an invalid document has no outcome: the document is written as declared.

MessageFormTest checks rules 1 and 5 over what the scratch fixtures log.

Levels ​

The level is behaviour, not tone. An error makes Result::isValid() false and the CLI exit with 1.

LevelWhenFor example
errorThe document is invalida required field missing, a duplicate operationId, a reference that resolves to nothing
errorSomething declared is losta class or member skipped, a component declared twice
errorThe configuration is wrongan unknown config option or key
warningThe output differs from what was declaredconst written as enum in 3.0, a docblock type falling back to the type hint, two operations folded by the merge strategy, a 3.1 feature left out of a 3.0 document
warningThe document is valid, but likely not what was meantan array without items in 3.1, a request body on GET
noticeA deprecated form still worksa classic type alias
notice, debugInformationthe components cleanup removed

A merge collision is a warning although one declaration loses: the merge strategy that decides it is the user's choice. So is what a compiler leaves out because the target version cannot express it, since one source may be built for several versions. What a compiler keeps although the version does not know it makes the document invalid, and is an error.

Exceptions are for code calling the API wrongly. The content being documented never throws: a class, member or attribute that cannot be read is skipped with an error, and the build goes on.
